# Go-live ワンページ — 今週お試し課金するための最小セット

**目的:** 「画面デモだけで終わる」ではなく、**実店舗の LINE 公式で 1 週間お試し**まで持っていき、対価を受け取れる状態にする。  
**製品呼び方:** OpenQARPで試作した店舗シフトPoC ／ Credit: Powered by OpenQARP

詳細手順: [../line_bridge/ONBOARDING_CHECKLIST.md](../line_bridge/ONBOARDING_CHECKLIST.md)

---

## 正直な前提（先に合意）

| やる | やらない（この週） |
|------|-------------------|
| お客様の **LINE 公式** + Messaging API | 開発者個人 LINE でスタッフ管理 |
| 店舗コード登録 → 希望休 → シフト見せて | 勤怠打刻・給与・36協定の自動判定 |
| 週次たたき台（古典）＋店長確認 | 既存シフト SaaS のリプレース宣言 |
| 少人数（目安 3〜15 名）・1 店舗 | マルチ店舗本番・SLA 付き運用 |

未設定の資格情報では **デモ／プレビューのみ**。ライブはお客様側の secret / token が必要。

---

## 今週の最小パッケージ（これだけ売る）

1. **キックオフ 30 分** … 画面デモ + 導入チェックリスト共有  
2. **接続作業 1 回** … Messaging API・Webhook・店舗作成・スタッフ 1〜2 名の試験送信（一緒に or 遠隔）  
3. **お試し期間** … 例: 5〜7 日。スタッフが `登録` / `希望休` / `シフト見せて` を実運用トライ  
4. **振り返り 20 分** … 感触確認 → 店舗カスタムの仮見積 or 終了

**価格感（会話用・仮）:** お試し **0〜数万円／回**。正式見積ではない。感触 OK なら月額数万円〜の店舗カスタムへ。

---

## 課金前チェック（全部 Yes で請求してよい）

- [ ] お客様が **自店の LINE 公式** を用意できる（または既にある）
- [ ] Channel secret / 長期トークンを **お客様または同席者** が扱える（こちらに永続保管しない方針を説明済み）
- [ ] Webhook が検証成功し、試験3発話（登録・希望休・シフト見せて）が通った
- [ ] 「たたき台であり店長確認前提／法規自動判定ではない／SaaS 置き換えではない」を口頭＋メモで伝えた
- [ ] お試しの **期間・対象店舗・人数目安・サポート窓口（チャット or メール）・金額** を1枚に書いた
- [ ] 終了後データの扱い（`stores.json` 削除・token 失効の依頼）を合意した

## 当日の台本（短縮）

1. 15 秒フック → 「サンプル店で今すぐ組む」（`SELLER_SCRIPT.md`）

## よくある止まり方 → 逃げ道

| 止まり | 逃げ道 |
|--------|--------|
| 公式アカウントがまだ無い | 作成手順だけ渡し、**画面デモお試し（安価／無料）** で日程を確保。接続は公式ができてから |
| IT 担当が不在 | チェックリスト PDF（本リポの md）を送り、トークン入力だけ同席してもらう |
| ngrok が不安 | 「お試し週は仮 URL。本番は御社サーバ or こちらで固定 HTTPS」と次フェーズに切る |
| 「今すぐ全店舗」 | 1 店舗・少人数に限定。拡大はカスタム見積 |

## 次の一歩（お試し後）

- 固定ドメイン Webhook・監視 → システム連携の個別見積  
- 量子比較は「載せ方の話」に留め、勝ち主張しない
